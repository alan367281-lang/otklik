# Отклик — проект решения

> Рабочее название было Key Manager; 21.10.2026 программа переименована
> в «Отклик» (идентификатор `app.otklik.desktop`, `otklik.exe`). При первом
> запуске настройки копируются из `%APPDATA%\app.keymanager.desktop`.

Свой менеджер горячих клавиш и заготовок для Windows. Главное: нажал
сочетание — в активное окно вставился текст. Вокруг этого: подстановки,
цепочки клавиш, запуск программ и ссылок, правила по приложениям,
текстовые сокращения и всплывающий поиск заготовок.

Стек: **Tauri 2** (Rust-ядро + окно на React 19 / Vite / TS).

---

## 1. Что умеет (объём первой версии)

| Возможность | Пример |
|---|---|
| Сочетание → текст | `Ctrl+Alt+1` → подпись письма |
| Подстановки | `{date}`, `{time}`, `{clipboard}`, `{cursor}` |
| Цепочка клавиш | `{Tab}Иванов{Tab}{wait 200}{Enter}` |
| Открыть | программу, папку, файл, сайт |
| Цепочка шагов | открыть сайт → подождать → вставить текст |
| Правила по приложениям | `Ctrl+Alt+1` в Telegram — одно, в Outlook — другое |
| Сокращения | набрал `;адр` → заменилось на адрес |
| Всплывающий поиск | сочетание → окошко у курсора → ищу заготовку → Enter |
| Все сочетания настраиваются | включая сочетание поиска и паузы; запись сочетания в окне «нажмите клавиши» |

### 2.1 Перехват клавиатуры — одна ловушка вместо RegisterHotKey

Решение: **один низкоуровневый хук `WH_KEYBOARD_LL`** в отдельном потоке
с собственным циклом сообщений. Он обслуживает и сочетания, и сокращения.

Почему не `RegisterHotKey` / `tauri-plugin-global-shortcut`:
- `RegisterHotKey` съедает сочетание **во всех** приложениях. Для правил
  «только в Telegram» нужно, чтобы в остальных окнах сочетание проходило
  насквозь. Хук решает это: «глотать» или «пропустить» мы выбираем сами,
  глядя на активное окно (так делает AutoHotkey с `#HotIf`).
- Сокращениям хук нужен всё равно, а держать два механизма — два источника
  конфликтов.

Правила работы хука (грабли, которые важно не наступить):
- **Обработчик должен возвращаться мгновенно.** Если он думает дольше
  `LowLevelHooksTimeout` (~300 мс — 1 с), Windows молча снимает хук, и
  программа «перестаёт работать» без ошибок. Поэтому в хуке только
  сопоставление, всё исполнение — через канал в поток исполнения.
- **Свои нажатия игнорируем** по метке `0x4B4D4B4D` («KMKM») в
  `dwExtraInfo`, иначе вставка текста сама себя перехватит. Чужие
  эмулированные нажатия (AutoHotkey, автотест) разбираем как обычные.
- Модификаторы спрашиваем у системы (`GetAsyncKeyState`) в момент нажатия
  основной клавиши, а не ведём свой учёт: свой учёт «залипает», если
  отпускание потерялось (Win+L, экран UAC). Запаздывание `GetAsyncKeyState`
  касается только текущей клавиши, а модификатор к этому моменту уже нажат.
- Удержание сочетания не повторяет действие: повторы нажатия глотаем.
- `Ctrl+Pause` Windows присылает как Break (`VK_CANCEL`) — переводим обратно.
- Сочетание с Win или одиночный Alt: после «проглатывания» посылаем
  фиктивную клавишу (`VK_E8`), чтобы не открылось меню «Пуск» / меню окна.
- Сторож раз в 5 с: если ввод был, а хук не вызывался больше минуты,
  хук ставится заново (Windows не сообщает, что сняла его).

### 2.2 Кто сейчас в фокусе

`GetForegroundWindow` → `GetWindowThreadProcessId` →
`QueryFullProcessImageNameW` → имя exe (`Telegram.exe`), плюс заголовок и
класс окна. Правило может фильтровать по exe, по заголовку (подстрока или
регулярка) и работать в режиме «только здесь» / «везде, кроме».
Приоритет: правило конкретного приложения важнее общего.

### 2.3 Вставка текста — два способа, выбор автоматически

| Способ | Как | Когда |
|---|---|---|
| **Буфер** (по умолчанию для длинного) | сохранить буфер → положить текст → `Ctrl+V` → через ~300 мс вернуть старый буфер | длинный, многострочный текст, форматирование |
| **Печать** (по умолчанию для короткого) | `SendInput` с `KEYEVENTF_UNICODE` посимвольно | короткое, и там, где вставка запрещена |

Порог по умолчанию ~100 символов, у правила можно указать способ явно.
Для каждого приложения можно задать своё «чем вставлять» (у терминалов
это `Ctrl+Shift+V` или `Shift+Insert`).

Грабли:
- **Ждём, пока отпустят модификаторы.** Сочетание нажато `Ctrl+Alt+1`, если
  сразу послать `Ctrl+V`, приложение получит `Ctrl+Alt+V`. Перед
  исполнением ждём отпускания (с тайм-аутом), при необходимости посылаем
  их «отжатие».
- **Раскладка RU/EN не важна**: печать идёт юникодом, а не кодами клавиш.
- **Журнал буфера Windows (Win+V) и менеджеры буфера**: временное
  содержимое помечаем форматом `ExcludeClipboardContentFromMonitorProcessing`,
  чтобы оно не засоряло историю.
- Буфер может быть занят другим процессом — `OpenClipboard` с повтором.
- Сохраняются и возвращаются **все** форматы буфера, лежащие в памяти
  (текст, HTML, картинки DIB, файлы из Проводника), до 64 МБ; форматы-объекты
  GDI пропускаются — картинки Windows всё равно дублирует в DIB.
- Перед Ctrl+V — пауза 100 мс: журнал буфера (Win+V) и менеджеры буфера
  на мгновение открывают его после каждого изменения, и программа, получив
  Ctrl+V в этот момент, молча ничего не вставляет (у Espanso та же пауза).
- Если за время ожидания человек сам что-то скопировал (номер версии
  буфера изменился), старое содержимое не возвращаем.
- Владелец буфера — невидимое окно потока исполнителя (`HWND_MESSAGE`).
- **Окна «от администратора»** не принимают ввод от обычного процесса
  (UIPI). В настройках — опция «запускать с правами администратора»;
  в интерфейсе честно подсказываем, почему не сработало.

### 2.4 Подстановки (`macros.rs`)

Разбираются при загрузке настроек (ошибка видна у правила сразу),
разворачиваются в момент срабатывания:

| Токен | Значение |
|---|---|
| `{date}` / `{дата}` | 30.09.2026 |
| `{date:%d %B %Y}` | 30 сентября 2026 — `%B` месяц в родительном падеже, `%Ми` — в именительном, `%A` — день недели по-русски |
| `{date+1d}`, `{date-2w}`, `{date+1m}`, `{date+1y}` | сдвиг даты (д/н/м/г тоже можно); 30 февраля → последний день месяца |
| `{time}` / `{время}`, `{time:%H:%M:%S}` | время |
| `{clipboard}` / `{буфер}` | текст из буфера обмена |
| `{cursor}` / `{курсор}` | где оставить курсор: после вставки жмём ← нужное число раз (перенос строки — один шаг) |
| `{{` `}}` | буквальные фигурные скобки |

В тексте незнакомое `{…}` остаётся как есть (код, JSON). В окне — кнопки
вставки токенов и предпросмотр «сейчас вставится» (`preview_text`).

### 2.5 Цепочки клавиш и шаги

```
Добрый день!{Enter}{Tab 2}{wait 150}{Ctrl+A}{Ctrl+C}
```

`{Enter}`, `{Tab}`, `{Ctrl+Shift+T}` — нажатие, `{Tab 3}` — трижды,
`{wait 200}` / `{пауза 200}` — пауза в мс, подстановки тоже работают,
остальное — текст (печатается юникодом). Здесь незнакомое `{…}` — ошибка:
опечатка в имени клавиши не должна молча напечататься.

`open` — сайт, папка, файл или программа через `ShellExecuteW` (как Win+R),
`%ПЕРЕМЕННЫЕ%` раскрываются, `args` — аргументы; перед запуском
`AllowSetForegroundWindow`, чтобы открытое вышло на передний план.

`steps` — цепочка из `text` / `keys` / `open` / `wait`; ошибка шага
останавливает цепочку и видна в журнале («шаг 2: …»).

### 2.6 Сокращения

- Хук помнит последние 64 набранных символа — **только в памяти**,
  никуда не пишет и не логирует. Символ — `ToUnicodeEx` с раскладкой
  **активного окна** и флагом `0x4` (не портит «мёртвые» клавиши для ё/é);
  нажатия, эмулированные юникодом (`VK_PACKET`, голосовой ввод), берутся
  из скан-кода.
- Память сбрасывается: щелчок мыши (`WH_MOUSE_LL`), смена окна, стрелки,
  Home/End, PgUp/PgDn, Insert/Delete, Esc, сочетания с Ctrl/Alt/Win,
  пауза. Backspace стирает последний символ.
- Режимы (`abbr_mode`): `instant` — сразу, как набрано; `word` — после
  пробела/Enter/знака и только целым словом (разделитель печатается после
  вставки); `auto` (по умолчанию) — начинается со знака (`;адр`) → сразу,
  с буквы (`спс`) → целым словом.
- Срабатывание: последнюю клавишу хук глотает, исполнитель стирает
  набранную часть Backspace'ом и выполняет действие (любое — текст,
  клавиши, открыть, цепочка).
- Конфликты видны у правила: одинаковые сокращения; «сразу»-сокращение
  внутри более длинного (`;а` и `;аб` — второе не успеет набраться).
- Правило может иметь и сочетание, и сокращение.

**Защита от печати не туда.** Исполнитель запоминает окно, в котором
сработало правило, и перед действием сверяет, что оно всё ещё активно;
если человек успел переключиться — действие отменяется с записью в журнал.

### 2.7 Всплывающий поиск (`search.rs`, `SearchApp.tsx`)

- Окно `search` создаётся скрытым при запуске (без рамки, поверх всех,
  без панели задач) — появляется мгновенно.
- Сочетание (`settings.search_hotkey`, по умолчанию `Ctrl+Alt+Space`)
  ловит хук → исполнитель запоминает окно, откуда вызвали, и показывает
  поиск у курсора мыши в пределах монитора (не помещается снизу — сверху).
  Перед показом — пустое нажатие, чтобы Windows отдала окну фокус.
- В списке — только заготовки, которые работают в этом приложении
  (`Rule::applies_to`). Нечёткий поиск (`lib/fuzzy.ts`): точное
  сокращение → начало названия → начало слова → подстрока → группа →
  текст → буквы по порядку. Внизу — полный текст выбранной.
- Enter → поиск прячется, фокус возвращается прежнему окну
  (`SetForegroundWindow` + ожидание до 300 мс), и уже там выполняется
  заготовка — тот же исполнитель со сверкой окна. Esc — закрыть и
  вернуть фокус. Щелчок в другое окно — просто закрыться.
- Номер заготовки сверяется с названием: если файл перечитали, пока
  поиск был открыт, — просим открыть заново, а не выполняем чужое.
- Сочетание поиска нельзя занять правилом (ошибка у правила), совпадение
  с паузой — предупреждение.

### 2.8 Открыть программу / папку / ссылку

`ShellExecuteW` (как «Выполнить»): exe с аргументами и рабочей папкой,
файл, папка, `https://…`, `mailto:`. Опция «если уже запущено —
переключиться на окно».

## 3. Настройки: окно + файл

Один источник правды — **`%APPDATA%\app.otklik.desktop\config.yaml`** (путь виден в окне и в трее; при запуске из песочницы MSIX `%APPDATA%` перенаправляется). Окно
настроек читает и пишет его, ручную правку файла программа подхватывает
на лету (`notify`), с проверкой: если в файле ошибка — остаёмся на
последней рабочей версии и показываем, где ошибка. Перед каждой записью —
копия в `backups/` (последние 20).

YAML выбран за многострочный текст без экранирования и знакомый формат
(как у Espanso).

```yaml
version: 1

settings:
  pause_hotkey: Ctrl+Alt+Pause
  search_hotkey: Ctrl+Alt+Space
  paste_threshold: 100          # длиннее — через буфер
  restore_clipboard_ms: 300

apps:                            # короткие имена для правил
  telegram: { exe: Telegram.exe }
  terminal: { exe: [WindowsTerminal.exe, cmd.exe], paste_keys: Ctrl+Shift+V }

snippets:
  - name: Подпись
    hotkey: Ctrl+Alt+1
    abbr: ";подп"
    text: |
      С уважением,
      Иван
      {date:%d.%m.%Y}

  - name: Подпись (Telegram — коротко)
    hotkey: Ctrl+Alt+1
    only_in: [telegram]          # перекрывает общее правило в Telegram
    text: "Иван"

  - name: Шаблон ответа
    abbr: ";отв"
    text: "Добрый день, {cursor}!\n\nСпасибо за письмо."

  - name: Заполнить форму
    hotkey: Ctrl+Alt+F
    keys: "Иванов{Tab}Иван{Tab}{wait 100}{Enter}"

  - name: Открыть Трекер
    hotkey: Ctrl+Alt+T
    open: https://tracker.yandex.ru

  - name: Утро
    hotkey: Ctrl+Alt+M
    steps:
      - open: https://mail.yandex.ru
      - wait: 1500
      - keys: "{Ctrl+L}"
```

Группы (папки) заготовок и теги — для списка и поиска.

## 4. Окно настроек (React)

- Слева — группы, в центре — список заготовок (название, сочетание,
  сокращение, где работает), справа — редактор.
- **Поле записи сочетания**: нажимаешь клавиши — поле показывает
  `Ctrl+Alt+1`. Записывает само окно (события клавиатуры, клавиша по
  физическому положению `e.code`, поэтому раскладка не важна), а ядро
  проверяет сочетание по тем же правилам, что и файл (`check_chord`).
  Хук ядра для этого не годится: **пока в фокусе окно Отклика,
  Windows его перехват не вызывает** (проверено: 0 вызовов хука).
  Следствие — внутри окна настроек сочетания не срабатывают. Часть
  сочетаний с Win окно не увидит: Windows забирает их раньше.
- **Сохранение**: черновик в окне, кнопка «Сохранить» / Ctrl+S. Перед
  записью — копия в `backups/`, запись через временный файл. Если файл за
  это время правили руками (другая версия по времени изменения), окно не
  затирает правки, а предлагает загрузить файл заново.
- Черновик проверяется ядром на лету (`check_config`) — те же сообщения,
  что при загрузке файла: конфликты сочетаний, неизвестные приложения.
- **Проверка конфликтов**: то же сочетание у другого правила в тех же
  приложениях; известные системные (`Win+L`, `Ctrl+Alt+Del`, `Alt+Tab`)
  нельзя; предупреждение о популярных (`Ctrl+C`, `Ctrl+Shift+Esc`).
- Кнопка «Проверить» — выполнить в тестовом поле прямо в окне.
- Выбор приложения из списка запущенных окон.
- Трей: пауза/продолжить, настройки, открыть config.yaml, выход.
- Автозапуск (`tauri-plugin-autostart`), один экземпляр
  (`tauri-plugin-single-instance`).

## 5. Структура проекта

```
otklik/
  docs/ARCHITECTURE.md
  src/                     React: окно настроек и окно поиска
  src-tauri/
    src/
      main.rs / lib.rs     сборка Tauri, плагины, запуск потоков
      tray.rs              значок и меню трея, пауза
      commands.rs          команды для окна
      engine.rs            общее состояние, перечитывание, журнал, наблюдение за файлом
      chord.rs             сочетания: разбор, запись, запрещённые (чистый)
      config/              модель config.yaml, стартовый файл (чистый)
      rules.rs             конфиг → таблицы, выбор правила по приложению (чистый)
      hook.rs              поток WH_KEYBOARD_LL, сторож
      executor/            поток исполнения; text.rs (буфер/печать);
                           дальше keys.rs, open.rs, vars.rs
      win/                 обёртки WinAPI: foreground, clipboard, input, modifiers
  scripts/smoke.ps1        сквозной автотест: своё окно, Alt+1, Ctrl+Alt+2
```

Rust-зависимости: `windows-sys` (сырые привязки; крейт `windows` на этой
машине съедает память при компиляции), `serde`, `serde_norway` (живой форк
`serde_yaml`), `chrono`, `parking_lot`; каналы — `std::sync::mpsc`,
наблюдение за файлом — опрос времени изменения раз в секунду (без `notify`).
Плагины Tauri: single-instance, opener, notification; autostart — на этапе 6.

Логика сопоставления и разбор мини-языка/подстановок — чистые функции
без WinAPI, покрываются `cargo test`.

## 6а. Выпуск (что сделано на этапе 6)

- **Автозапуск** (`tauri-plugin-autostart`, реестр Run) — переключатель
  в «Общих»; при каждом старте путь перезаписывается (`sync_autostart`): после переустановки он мог измениться.
- **Права администратора** (`admin.rs`). Без них ввод в окна
  администратора Windows отбрасывает (UIPI). В «Общих» видно, как
  программа запущена; «Перезапустить от администратора» — UAC, новая
  копия стартует через `cmd /c timeout 2 & start` (одна копия на
  компьютер — старая должна успеть выйти). «Запускать при входе от
  администратора» — задача Планировщика из XML: наивысшие права, без
  ограничения «только от сети» (иначе на ноутбуке от батареи задача
  молча не стартует) и без лимита 72 часа; обычный автозапуск при этом
  выключается, чтобы не стартовали две копии.
- **Импорт из Espanso** (`espanso.rs`): `%APPDATA%\espanso\match\**.yml`
  (кроме файлов на «_»). Переносятся `trigger`/`triggers` → сокращение,
  `replace` (и `markdown`/`html` — как текст), `word: true` → «целым
  словом», `$|$` → `{cursor}`, переменные `date` (формат chrono тот же) и
  `clipboard`. Формы, регулярки, скрипты, картинки — в списке
  «не переносится» с причиной. Добавляется в черновик в группу «Espanso»,
  уже существующие сокращения не дублируются.
- **Установщик**: NSIS, установка для текущего пользователя (без прав
  администратора), русский язык. `npm run build` →
  `D:\dev\cargo-target\release\bundle\nsis\Отклик_0.1.0_x64-setup.exe`.

## 6б. macOS и обновления (версия 0.2.0)

- **Две системы — один код.** Всё системное — за фасадом `platform`
  (`win/` и `mac/` с одинаковыми модулями: `hook`, `input`, `modifiers`,
  `clipboard`, `foreground`, `shell`, `apps`, `admin`). Решения хука
  (сочетание, набор, сокращения) общие — `hook.rs`; платформенный перехват
  только переводит события в коды Windows (VK) и спрашивает, глотать ли.
- **Mac:** перехват — `CGEventTap` (свой поток с `CFRunLoop`; отключение
  по таймауту — включаем обратно; «глотание» — тип события `Null`);
  эмуляция — `CGEventPost` с меткой в `kCGEventSourceUserData`; символ для
  сокращений macOS кладёт в событие сам; буфер — `NSPasteboard` (все типы
  всех элементов, пометки `org.nspasteboard.TransientType`); приложение в
  фокусе — `NSWorkspace`, заголовок окна — Accessibility; вместо прав
  администратора — разрешение «Универсальный доступ» (без него
  `CGEventTapCreate` пуст; поток ждёт и стартует сам, когда разрешат).
- **Один config.yaml на обе системы:** Cmd = Win, Option = Alt;
  `Telegram.exe` и `Telegram.app` сравниваются без хвоста. Стартовые
  сочетания на Mac — Ctrl+Option (Option+цифра печатает «¡», Pause нет).
- **Обновления:** `tauri-plugin-updater`, `latest.json` последнего выпуска;
  проверка через 20 с после запуска и раз в 6 часов; ставим только по
  кнопке (полоса в окне, пункт трея). Подпись minisign: открытый ключ — в
  `tauri.conf.json`, закрытый — `~/.tauri/otklik.key` и секрет GitHub
  `TAURI_SIGNING_PRIVATE_KEY`. Сборку и выпуск обеих систем делает
  GitHub Actions; имена файлов в выпуске латиницей и постоянные.

## 7. Известные ограничения

- В окна «от администратора», экран входа и UAC ввод не пройдёт без
  запуска программы с правами администратора.
- Некоторые игры и программы с античитом / защитой ввода (банк-клиенты,
  поля паролей в отдельных приложениях) игнорируют эмулированный ввод.
- Неподписанный exe с хуком клавиатуры может насторожить антивирус —
  понадобится исключение или подпись.
